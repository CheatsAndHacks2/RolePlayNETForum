# RolePlay.NET — запуск и деплой

## Важно про базу данных

В исходном проекте уже есть слой данных на **PostgreSQL + Drizzle ORM**. Он используется почти во всех страницах и API. Это не JSONbin-интеграция: просто заменить URL базы на JSONbin нельзя — потребуется переписать слой запросов и транзакционную логику. Поэтому текущая версия сохраняет существующую PostgreSQL-архитектуру, а JSONbin пока не подключён.

Для работающего деплоя нужен PostgreSQL, доступный из Vercel (например, Neon или Supabase PostgreSQL). В Vercel → Project → Settings → Environment Variables добавьте `DATABASE_URL`.

## Переменные окружения

Скопируйте `.env.example` в `.env.local` для локального запуска.

- `DATABASE_URL` — обязательная строка подключения PostgreSQL.
- `FOUNDER_USERNAME` — ник первого владельца (необязательно).
- `FOUNDER_PASSWORD` — пароль первого владельца (необязательно, но обязателен вместе с ником).

Задайте `FOUNDER_USERNAME` и `FOUNDER_PASSWORD` до первого запуска, чтобы автоматически создать защищённый аккаунт основателя. В проекте больше нет встроенных логинов и паролей. Не используйте слабый или повторно используемый пароль.

## Локальный запуск

```bash
npm install
cp .env.example .env.local
# Заполните DATABASE_URL и при необходимости FOUNDER_USERNAME / FOUNDER_PASSWORD
npm run dev
```

## Деплой на Vercel

1. Загрузите репозиторий в GitHub.
2. В Vercel нажмите **Add New → Project** и импортируйте репозиторий.
3. Framework Preset: **Next.js** (определяется автоматически).
4. Добавьте `DATABASE_URL` и, если нужен владелец, `FOUNDER_USERNAME` + `FOUNDER_PASSWORD`.
5. Deploy.

`/api/health` проверяет доступность БД. Если ответ содержит `database: unavailable`, проверьте `DATABASE_URL` и доступность PostgreSQL.

## Инициализация схемы БД

Схема таблиц находится в `src/db/schema.ts`. Перед первым использованием база должна содержать таблицы из этой схемы. Сгенерируйте миграции Drizzle и примените их к вашей базе:

```bash
npx drizzle-kit generate
npx drizzle-kit migrate
```

Убедитесь, что конфигурация Drizzle указывает на тот же `DATABASE_URL`, что и Vercel.

## Что изменено

- Убраны автоматически создаваемые вымышленные аккаунты, тестовые публикации и искусственная активность.
- Убраны встроенные пароли основателей. Учётка владельца создаётся только из заданных вами переменных окружения.
- Сохраняются системные роли, пустая структура разделов и префиксы тем, чтобы новый форум был готов к наполнению реальными пользователями.
- Добавлена конфигурация Vercel и health-check с корректным статусом 503 при недоступной БД.

## Ограничения текущей версии

JSONbin намеренно не подключён. Если хотите использовать именно JSONbin без PostgreSQL, потребуется отдельная миграция всего слоя данных: пользователи, сессии, разделы, темы, сообщения, лайки, жалобы, настройки и административные операции. Простое добавление `JSONBIN_ID` в env не сделает существующий ORM-код совместимым с JSONbin.
